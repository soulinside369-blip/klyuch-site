# Запуск КЛЮЧа на своём домене

Сайт уже собран и проверен. Для запуска нужны хостинг с PHP в России, домен, Telegram-бот и номер счётчика Метрики.
Секреты (пароли, токен бота) в репозиторий и в чат не попадают — только в настройки хостинга и GitHub.

## 0. Текущая схема (26.10.2026): Yandex Cloud, 0 ₽/мес

Сайт — статика в Object Storage (бакет `xn--80aqcff3bzb5c.xn--p1ai` = айтиключ.рф), HTTPS — бесплатный Let's Encrypt из Certificate Manager,
DNS — Cloud DNS (у регистратора Timeweb прописаны `ns1.yandexcloud.net`, `ns2.yandexcloud.net`). Выкладка — workflow
«Выкладка в Yandex Cloud» при каждом пуше в main (секреты `YC_KEY_ID`, `YC_SECRET`). Почему не GitHub Pages: проверка DNS у GitHub
зависает на российских доменах, сертификат не выпускается (сентябрь–октябрь 2026).

Настройка один раз:
1. Консоль Yandex Cloud → Object Storage → бакет с именем `xn--80aqcff3bzb5c.xn--p1ai`, публичный доступ на чтение объектов.
   Вкладка «Веб-сайт» → «Хостинг», главная `index.html`, ошибка `404.html`.
2. Сервисный аккаунт с ролью `storage.editor` → статический ключ доступа → в GitHub-секреты `YC_KEY_ID` и `YC_SECRET`.
3. Cloud DNS → публичная зона `xn--80aqcff3bzb5c.xn--p1ai.` → ANAME на `xn--80aqcff3bzb5c.xn--p1ai.website.yandexcloud.net`, CNAME `www` туда же.
   У регистратора (Timeweb) — сменить NS на `ns1.yandexcloud.net`, `ns2.yandexcloud.net`.
4. Certificate Manager → сертификат Let's Encrypt для домена (проверка через DNS) → в бакете «HTTPS» выбрать его.
5. Биллинг → бюджет с уведомлением (например, 50 ₽), чтобы не было сюрпризов.

## 1. Хостинг и домен (вариант с PHP-хостингом)

1. Хостинг с PHP 8+ и SSL в РФ: Timeweb, Beget, Selectel, Reg.ru — подойдёт самый простой тариф.
2. Домен **айтиключ.рф** (куплен 26.10.2026; в настройках хостинга может понадобиться запись `xn--80aqcff3bzb5c.xn--p1ai`) направить на хостинг, включить бесплатный SSL (Let's Encrypt) — сайт должен открываться по `https://`.
3. В панели хостинга создать FTP-доступ к папке сайта (`public_html`).

## 2. Форма → Telegram

1. В Telegram: `@BotFather` → `/newbot` → получить **токен**.
2. Написать боту любое сообщение, затем узнать свой **chat_id** (`@userinfobot`). Для группы — добавить бота в группу.
3. На хостинге в папке сайта: скопировать `api/config.example.php` → `api/config.php`, вписать токен и chat_id.
4. Выбрать режим `telegram_personal`:
   - `true` — имя и контакт приходят прямо в Telegram. Это трансграничная передача персональных данных: до начала —
     уведомить Роскомнадзор (см. п. 5).
   - `false` — в Telegram приходит только номер заявки, сами данные лежат на сервере в `api/leads/leads.csv`
     (папка закрыта от доступа из интернета, скачать — через файловый менеджер хостинга).
5. Проверка: отправить тестовую заявку с сайта — должно прийти сообщение в Telegram и строка в `leads.csv`.

## 3. Выкладка

Вариант А — вручную: `npm ci && npm run build`, залить содержимое `dist/` в `public_html`.

Вариант Б — из GitHub одной кнопкой:
1. GitHub → Settings → Secrets and variables → Actions → добавить секреты `FTP_SERVER`, `FTP_USERNAME`, `FTP_PASSWORD`, `SITE_URL`.
2. Actions → «Выкладка на хостинг (FTP)» → Run workflow. `api/config.php` и заявки на сервере не перезаписываются.

## 4. Яндекс Метрика

1. metrika.yandex.ru → «Добавить счётчик» → адрес сайта. Вебвизор не включать (на сайте он выключен).
2. Номер счётчика вписать в `src/data/site.ts` → `analytics.metrikaId` и выложить сайт заново.
   Со счётчиком на сайте появится короткая плашка про cookie (требование к прозрачности обработки данных).
3. В Метрике: «Цели» → «JavaScript-событие», по одной на идентификатор:

| Идентификатор | Что значит |
|---|---|
| `portfolio` | открыл кейсы |
| `case_open` | раскрыл карточку кейса |
| `contacts` | дошёл до контактов |
| `cta` | нажал «Разобрать мою ситуацию» |
| `telegram` | перешёл в Telegram |
| `phone` | нажал на номер телефона |
| `form_error` | ошибся в форме |
| `lead` | **заявка отправлена** — главная цель |
| `trailer_full` / `trailer_skip` | досмотрел / пропустил трейлер |
| `sound_on` | включил звук |

Воронка для отчёта: `portfolio` → `contacts` → `lead`.

## 5. Персональные данные (152-ФЗ)

Тексты политики и согласия уже на сайте (`/privacy/`, `/consent/`), подготовлены по закону — перед запуском показать юристу.
Что сделать владельцу:

1. Вписать реквизиты оператора в `src/data/site.ts` (`brand.legal`, `brand.address`, `brand.email`) и хостинг-провайдера в
   `src/data/legal.ts` (раздел 7 политики).
2. Подать уведомление об обработке персональных данных в Роскомнадзор (pd.rkn.gov.ru) — до начала сбора заявок.
3. Если `telegram_personal = true` — там же уведомить о трансграничной передаче (Telegram).
4. Назначить ответственного за обработку персональных данных.
